# Finance API

Finance API — мой учебный Backend-проект на Python и FastAPI для учёта личных финансов. В приложении можно создавать счета и категории, записывать доходы и расходы, переводить деньги между счетами и получать статистику.

Проект разрабатываю для практики и подготовки к стажировке или работе Junior Python Backend Developer. Начинал с хранения данных в обычных словарях Python, затем перенёс приложение на PostgreSQL с использованием SQLAlchemy и Alembic.

## Что реализовано

**Счета**
- Создание, просмотр и удаление счетов.
- Поддержка валют RUB, USD и EUR.
- Проверка уникальности названия счёта и допустимого начального баланса.

**Категории**
- Создание категорий доходов (`income`) и расходов (`expense`).
- Просмотр и удаление категорий.
- Проверка типа категории при создании финансовой операции.

**Доходы и расходы**
- Создание операций с суммой, категорией, датой и необязательным описанием.
- Автоматическое изменение баланса счёта.
- Проверка достаточности средств при расходах.
- Просмотр истории операций и удаление с обратной корректировкой баланса.

**Переводы**
- Переводы между двумя счетами в одной валюте.
- Проверка баланса отправителя.
- Просмотр и удаление переводов с возвратом средств на исходный счёт.

**Статистика**
- Получение балансов счетов.
- Подсчёт сумм доходов или расходов по категориям.
- Просмотр операций за выбранный период.

При работе с денежными суммами использую `Decimal`. Данные запросов проверяются через Pydantic. Для операций с изменением балансов применяются транзакции БД и блокировки строк `SELECT ... FOR UPDATE`, чтобы снизить риск ошибок при одновременных запросах.

## Используемые технологии

- **Python 3.14** — основной язык.
- **FastAPI** — REST API и автоматическая документация Swagger / OpenAPI.
- **Pydantic 2** — валидация входных данных.
- **PostgreSQL 18** — хранение данных.
- **SQLAlchemy 2.0** — асинхронная работа с базой данных через `AsyncSession`.
- **Alembic** — миграции схемы БД.
- **Docker** — запуск PostgreSQL локально.
- **Git / GitHub** — контроль версий.

## Структура проекта

```text
app/
├── api/v1/          # Маршруты и обработка HTTP-запросов
├── schemas/         # Pydantic-схемы
├── service/         # Бизнес-логика
├── repository/      # Запросы к базе данных
├── models/          # SQLAlchemy-модели
├── core/            # Настройки приложения
├── database.py      # Подключение к PostgreSQL и фабрика сессий
└── dependencies.py  # Зависимость для получения сессии БД

migrations/           # Миграции Alembic
alembic.ini
main.py               # Точка входа FastAPI
```

Приложение разделено на несколько слоёв:

`Router → Service → Repository → Database`

Маршруты принимают HTTP-запросы, сервисы отвечают за проверки и бизнес-логику, а репозитории работают с данными через SQLAlchemy. Такое разделение помогает не смешивать всю логику в обработчиках запросов.

## Запуск проекта

Для запуска понадобятся Python 3.14, PostgreSQL и Git. Ниже пример для Linux; PostgreSQL можно запустить через Docker.

### 1. Клонировать репозиторий

```bash
git clone https://github.com/rafkorel/finance-api.git
cd finance-api
```

### 2. Создать виртуальное окружение и установить зависимости

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3. Запустить PostgreSQL

Например, через Docker:

```bash
docker run --name finance-postgres \
  -e POSTGRES_USER=finance \
  -e POSTGRES_PASSWORD=finance_dev \
  -e POSTGRES_DB=finance_db \
  -p 5432:5432 \
  -v finance_pgdata:/var/lib/postgresql \
  -d postgres:18
```

Если PostgreSQL уже работает локально, можно использовать существующую базу данных и указать её настройки на следующем шаге.

### 4. Настроить подключение к базе данных

Создать в корне проекта файл `.env` со строкой:

```env
DATABASE_URL=postgresql+psycopg://finance:finance_dev@localhost:5432/finance_db
```

Это пример для PostgreSQL из команды выше. При использовании другой БД нужно указать свои параметры подключения. Файл `.env` не должен попадать в Git.

### 5. Применить миграции и запустить приложение

```bash
alembic upgrade head
uvicorn main:app --reload
```

После запуска API будет доступно по адресу `http://127.0.0.1:8000`.

**Swagger UI:** `http://127.0.0.1:8000/docs` — здесь можно посмотреть все эндпоинты и отправлять тестовые запросы.

## Основные эндпоинты

Все маршруты начинаются с `/api/v1`.

| Раздел | Эндпоинты |
| --- | --- |
| Счета | `POST /accounts`, `GET /accounts`, `GET /accounts/{account_id}`, `DELETE /accounts/{account_id}` |
| Категории | `POST /categories`, `GET /categories`, `GET /categories/{category_id}`, `DELETE /categories/{category_id}` |
| Операции | `POST /transactions/income`, `POST /transactions/expense`, `GET /transactions`, `GET /transactions/{transaction_id}`, `DELETE /transactions/{transaction_id}` |
| Переводы | `POST /transfers`, `GET /transfers`, `GET /transfers/{transfer_id}`, `DELETE /transfers/{transfer_id}` |
| Статистика | `GET /statistics/balance`, `GET /statistics/categories`, `GET /statistics/period` |

Например, для создания счёта нужно отправить `POST /api/v1/accounts`:

```json
{
  "name": "Основной счёт",
  "balance": "10000.00",
  "currency": "RUB"
}
```

Для создания дохода — `POST /api/v1/transactions/income`:

```json
{
  "account_id": 1,
  "category_id": 1,
  "amount": "5000.00",
  "description": "Зарплата",
  "date": "2026-10-01"
}
```

Перед созданием дохода в базе должны существовать указанные счёт и категория типа `income`. Поля запросов и ответы можно посмотреть в Swagger UI.

## Текущее состояние проекта

Приложение находится в разработке. Основные эндпоинты проверял вручную через Swagger, в том числе сценарии с одновременными запросами. Автоматические тесты пока не добавлены.

Текущие ограничения:
- Переводы между счетами с разными валютами не поддерживаются. Работа с курсами валют ещё разрабатывается.
- Общая статистика балансов пока складывает суммы без конвертации валют. Если счета открыты в разных валютах, общий итог не стоит считать корректной суммой в одной валюте.
- Авторизация пользователей пока отсутствует, поэтому приложение не предназначено для публичного использования с реальными финансовыми данными.
